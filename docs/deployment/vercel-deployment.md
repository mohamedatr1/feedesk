## What was deployed

- Vercel Services project with two services:
  - `web` — Next.js 16, public at `/*`.
  - `api` — FastAPI, private; no public rewrite.
- Service binding: `web` → `api`, injected as `API_URL`.
- Browser `/api/*` requests go through `apps/web/app/api/[...path]/route.ts` to FastAPI.
- Neon Postgres `feedesk-production` (Free plan, `iad1`) connected to Production.
- Production environment uses `APP_BASE_URL=https://feedesk-one.vercel.app`.
- `vercel project protection disable --sso` was applied so the app is publicly reachable; application authentication remains enforced.

## Database setup

The local workstation could not reach Neon on port 5432. Migrations and seed run from the Vercel build hook:

- `apps/api/vercel_build.py`
- `[tool.vercel.scripts] build = "python vercel_build.py"`

The hook uses `DATABASE_URL_UNPOOLED` when available, runs `alembic upgrade head`, then `app.seed`. It is idempotent; later builds reported existing admin/template/settings without resetting data.

## Known limitations on this deployment

- **Uploads are ephemeral.** `UPLOAD_DIR=/tmp/feedesk-uploads`; source files can disappear between function instances. Production requires object storage/Vercel Blob behind `apps/api/app/imports/storage.py`.
- **OCR is disabled.** Tesseract/Arabic data are not present on Vercel.
- **Messaging worker is not running.** `apps/api/app/worker.py` is a polling process; Vercel needs a cron/queue/daemon design before live messaging.
- **No custom domain.** The assigned production alias is `feedesk-one.vercel.app`; `feedesk.vercel.app` is already used by another project.
- **Preview database is not provisioned.** Only Production is connected to Neon.
- **No backups/monitoring configured yet.** The app is live, but production operations are not complete.
- **Git deployment linkage** reported the repository as already connected; CLI deployments are working, but confirm GitHub auto-deploy behavior in the Vercel dashboard before relying on it.
